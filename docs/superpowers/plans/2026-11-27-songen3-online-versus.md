# 尊厳を賭けようか3 オンライン対戦のデザイン修正と公開計画

> 実装時は下の作業順に、変更前に検査を作り、変更後に通ることを確認してから次へ進む。

**目標**　無印の画面の見た目と遊び方を引き継いだ『尊厳を賭けようか3』を、招待制のオンライン1対1で遊べるようにする。

**構成**　既存の6画面、通信仕様番号1、サーバーによる判定を土台にする。画面はGitHub Pages、対戦はCloudflare Workersを使う。デザインの合格判定、ゲーム単体の公開、実験場への掲載はそれぞれ確認する。

**技術**　JavaScriptモジュール、Node.js 22、pnpm 10.4.1、Vite、Vitest、Playwright WebKit、Cloudflare Wrangler、GitHub Actions。

**仕様**　[オンライン対戦要件仕様書](../../online-versus-requirements.md)。見た目と操作の原本は [無印の固定コミット 060b251](https://github.com/chameleonjp-lab/songen_wo_kakeyouka/blob/060b251a7016725bfd4e7886936eabf223b092d0/index.html)。

## 全作業の共通条件

- 無印は `060b251` に固定する。旧3D版の `ef0e1d4` は公開の復元用として扱う。
- 6画面はホーム、プレイヤー登録、待機室、ゲーム、結果発表、スコア結果の順。オンライン版の部屋・準備・再戦の操作と、無印の見た目を組み合わせる。
- 左右はホストが左、ゲストが右。1秒60回、180秒で引き分けの計算はサーバーが確定する。画面サイズ変更は表示だけに反映する。
- 15言語を維持する。iPhone Safariの縦画面、402×700相当の短い縦画面、横画面で確認する。
- 実験場への掲載とランキングは公開保留。ゲーム単体の本番切り替えは、照合結果と対戦の確認をそろえ、ユーザーが公開を指示したときに行う。ブランチのマージはユーザーが行う。

## 初稿の敵対的検証と修正

初稿では無印の外観を引き継ぎ、縦画面で比較してゲームを公開する方針とした。公開物、原本と現行コード、公開の設定を突き合わせ、次の不足を作業1〜4へ反映した。

| 初稿で起こり得ること | 修正版の確認 |
| --- | --- |
| 無印の色と絵文字だけを拾い、操作ボタンの順番やスコア欄が変わったままになる | 原本のホーム、対戦、決着、スコア画面を基準画像にし、対戦の操作配置と数字を別途検査する |
| 無印の決着画面を移した結果、試合終了時に実際にいた位置と壊れた部位が分からなくなる | 無印の決着カードの見た目と、サーバーが保存した最終盤面を組み合わせ、同じ試合ID・計算回・部位・位置を照合する |
| 390×844の見た目だけが合い、短い画面や横向きで操作が隠れる | 402×700、横向き、長い翻訳、画面回転後まで確認する |
| 実験場を公開しないとゲーム本体を公開できず、公開URLが旧3D版にとどまる | ランキング保留中もゲーム単体の公開条件を判定できるようにする。保留中はランキングボタンと公開ランキングへの送信を止める |
| マージや配信処理の成功だけで「公開済み」と判断する。または旧画面と新サーバーが混在する | 公開URLから提供された版を確認し、公開URLを開いた二人がルーム作成から再戦まで進めることを確かめる |

- [ ] `tests/browser/online.spec.js` に、対戦の時間・スコア・スタミナ、丸い攻撃・ガードボタンの相対位置、左右の部位、最終盤面を検査する試験を追加する。変更前は無印と異なる表示の検査で失敗することを確認する。
- [ ] `web/index.html`、`web/style.css`、`web/js/view.js`、`web/js/result-view.js` に作業1の画面を反映する。試合中の得点は受信済みの `statsBySeat[自分の席].score` を表示し、決着は確定した `scoreBySeat` を使う。決着画面は `finalSnapshot` にある座標と部位の破損を再描画し、⑥へ進むまで固定する。
- [ ] 名前や「あなた」の表示を移しても、ホスト左・ゲスト右の判定と、十字パッドの入力方法を維持する。盤面の拡大率を変えても、通信する座標・攻撃判定・得点式を維持する。
- [ ] `pnpm check`、`pnpm test`、`pnpm test:browser`、`pnpm build` を実行する。作業1の比較画像で、対戦画面と決着画面の部位、金色の得点、ボタンの配色と位置を確認する。短い縦画面、横画面、長い翻訳、回転直後に6操作が押せて、⑤の両者の部位と次へ進むボタンが見えることを確かめる。

## 作業3　実験場の公開保留をゲーム本体から分ける

- [ ] `.github/workflows/pages.yml` と `worker/index.js` に、ランキングを保留したまま本体を公開できる検査を追加する。ゲームの公開条件は、本番対戦サーバーのURL、通信仕様番号1、ルーム受付、GitHub Pagesからの接続、画面とサーバーのランキング設定の一致とする。ランキングを同時公開する設定を明示した場合に、ランキングの応答も必須とする。
- [ ] 実装時はWorkerの `RANKINGS_PUBLIC` と画面の `VITE_RANKINGS_PUBLIC` を用意し、指定なしは保留扱いにする。サーバーが `/v1/health` で返す `rankingsPublic` の真偽値を配信処理で照合する。保留中は①・⑥のランキングボタンと送信中表示を隠し、名前の有無にかかわらず②から⑥まで遊べるようにする。
- [ ] `worker/room.js` と `worker/ranking.js` で、保留中に開始した試合の開始・結果を公開ランキングの送信待ちに入れない。サーバーによる決着と個人のスコア結果は保存する。公開中にすでに作られた送信待ちデータの処理も、現在の設定が保留なら停止する。
- [ ] 画面とサーバーの設定違い、ランキング保留中の対戦、ランキング公開時に連携先が応答しない場合を検査する。公開保留の対戦で、外部の開始・得点送信がゼロ、⑥のスコア表示は成功することを確認する。
